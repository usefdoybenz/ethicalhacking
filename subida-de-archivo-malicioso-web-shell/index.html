Subida de Archivos Maliciosos

Web Shells y Técnicas de Penetración

¿Qué es una Web Shell?

Definición: Una Web Shell es un script o programa malicioso que se instala en un servidor web para proporcionar a los atacantes acceso remoto y control completo sobre el sistema a través de una interfaz basada en web. Esta herramienta permite ejecutar comandos del sistema, manipular archivos y llevar a cabo acciones maliciosas en el servidor comprometido.

Nivel de amenaza: Crítico

Las Web Shells representan una de las amenazas más serias en ciberseguridad, ya que permiten:

  • Ejecución remota de comandos: Control total del sistema operativo
  • Persistencia: Mantienen acceso continuo al servidor
  • Escalación de privilegios: Potencial para obtener permisos de administrador
  • Movimiento lateral: Compromiso de otros sistemas en la red
  • Exfiltración de datos: Acceso a información sensible

Impacto de Seguridad: Una Web Shell exitosa puede resultar en compromiso completo del servidor, pérdida de datos confidenciales, instalación de malware adicional y uso del servidor como plataforma para ataques posteriores.

Tipos de Web Shells

Por Lenguaje de Programación:

  • PHP Shells: Las más comunes (c99.php, r57.php, WSO)
  • ASP/ASPX Shells: Para servidores Windows IIS
  • JSP Shells: Para aplicaciones Java
  • Python Shells: Para frameworks Django/Flask

Por Funcionalidad:

  • Shells Simples: Ejecución básica de comandos
  • Shells Avanzadas: Interfaz gráfica completa
  • Backdoors: Acceso encubierto y persistente
  • Shells de Conexión Inversa: Reverse shells para evadir firewalls

Fase 4: Subida y Ejecución

Subimos el archivo malicioso a través del formulario web y lo ejecutamos:

Ejecución del Payload
# Acceso directo via navegador http://soccer.htb/tiny/uploads/malicious.php # Ejecución con cURL curl http://soccer.htb/tiny/uploads/malicious.php # Ejecución con wget wget -qO- http://soccer.htb/tiny/uploads/malicious.php

Resultado Exitoso: Una vez ejecutado el payload, obtenemos una reverse shell en nuestro listener, proporcionando acceso completo al sistema comprometido.

Técnicas de Evasión:

  • Ofuscación de código: Codificación Base64, ROT13, o custom encoding
  • Extensiones dobles: file.php.jpg, file.php.txt
  • Null byte injection: file.php%00.jpg
  • Case sensitivity: .PHP, .pHp, .Php
  • MIME type spoofing: Manipulación de Content-Type headers

Medidas de Protección

Controles de Seguridad Esenciales:

  • Validación de extensiones: Lista blanca de tipos de archivo permitidos
  • Verificación de contenido: Análisis del contenido real del archivo
  • Sandbox execution: Ejecución en entornos aislados
  • Límites de tamaño: Restricciones en el tamaño de archivo
  • Análisis antimalware: Escáner de malware integrado

Detección y Respuesta

Indicadores de Compromiso (IOCs):

  • Archivos sospechosos: Scripts con nombres inusuales en directorios web
  • Conexiones de red: Tráfico TCP saliente no autorizado
  • Logs de acceso: Requests a archivos PHP en directorios de upload
  • Procesos anómalos: Shells iniciados por proceso web

Comandos de Detección:

Búsqueda de Web Shells
# Buscar archivos PHP en directorios de upload find /var/www -name "*.php" -path "*/upload*" -ls # Buscar strings sospechosos en archivos PHP grep -r "system\|exec\|shell_exec\|passthru" /var/www/html/uploads/ # Monitorear conexiones de red netstat -antup | grep :80 # Revisar logs de acceso web tail -f /var/log/apache2/access.log | grep -i "\.php"

Consideraciones Éticas y Legales

Advertencia Legal: Las técnicas de Web Shell solo deben utilizarse en:

  • Sistemas propios o con autorización explícita por escrito
  • Entornos de pentesting con contratos legales válidos
  • Plataformas de práctica autorizadas (HTB, TryHackMe, VulnHub)
  • Laboratorios controlados de ciberseguridad

La instalación no autorizada de Web Shells constituye un delito grave de acceso ilegal a sistemas informáticos según las legislaciones locales e internacionales.

Uso Ético: Estas técnicas deben emplearse exclusivamente para mejorar la seguridad, identificar vulnerabilidades y proteger sistemas. Nunca para causar daño, robar información o comprometer sistemas sin autorización.
